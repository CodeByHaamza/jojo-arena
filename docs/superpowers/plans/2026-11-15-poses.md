# Poses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real, sourced JoJo poses for every fighter — 3 alone, 3 with the Stand for Stand users — picked on the select screen and played by the Pose key.

**Architecture:** The sprite generator gains bendable limbs (`Limb`: elbows, knees, hip sway) and `[poses.*]` in look files, written into the sheets as `pose_<id>` animations with a `[poses.*]` table. At runtime a per-player `Loadout` (in `GameContext`) says which pose to play; the fight view plays it, and the Stand plays its matching pose beside its user. The select screen gets a loadout step after a fighter is picked.

**Tech Stack:** Python 3.12, pygame-ce, pytest; generator in `tools/spritegen/`.

**Spec:** `docs/superpowers/specs/2026-11-15-poses-design.md`

## Global Constraints

- Code, names, comments in English; game texts French and English (`label`, `label_en`).
- Every pose cites its source in the look file (CLAUDE.md: nothing about a character is invented).
- A straight limb renders exactly the pixels it renders today: `tests/test_spritegen.py::test_generated_sheets_are_up_to_date` must pass before any pose is added (Task 1), and every regenerated sheet is committed with the look that changed it.
- The simulation (`combat/`) does not change: poses are view-only.
- Commits conventional, no AI mention, no `Co-Authored-By`.

## Review Focus

- A loadout naming a pose the sheet no longer has (old settings.json): falls back to the first pose of that kind, then to the generic `pose` → Task 3 test `test_a_pose_that_is_gone_falls_back`.
- A Stand user who poses with the Stand out but the Stand sheet lacks that pose: the Stand plays its generic `pose` → Task 3 test.
- Mirror match, both players on the same fighter with different poses: each side plays its own → Task 3 test.
- A fighter with no poses at all (mannequin, gang friends): the select screen skips the loadout step → Task 4 test.
- A bent limb at the edge of the cell (hand raised high): stays inside the cell like hands do today → Task 1 test.

### Task 1: Bendable limbs

**Files:** Modify `tools/spritegen/skeleton.py` (Pose fields, `Limb`, `Skeleton.arms/legs`, `blend`), `tools/spritegen/body.py`, `tools/spritegen/parts.py` (every part that follows an arm or a leg), `tools/spritegen/look.py` (POINT_FIELDS). Test: `tests/test_spritegen.py`.

**Interfaces — Produces:**
- `Pose.elbow_l/elbow_r/knee_l/knee_r: Point = (0.0, 0.0)`, `Pose.sway: float = 0.0`.
- `class Limb(root: Point, joint: Point, end: Point, bent: bool)` with `point(t: float) -> Point`, `pixels(r: float, t0: float = 0.0, t1: float = 1.0) -> set[Pixel]`, `path(t0, t1) -> list[Point]`, `end_direction() -> Point` (unit vector of the last segment).
- `Skeleton.arms: tuple[Limb, Limb]`, `Skeleton.legs: tuple[Limb, Limb]` (same order as `hands`/`feet`).

- [ ] Step 1: tests — `test_a_straight_limb_is_the_old_capsule` (Limb with joint at midpoint, `pixels(r)` == `capsule(...)`, `point(t)` == `_lerp`), `test_a_bent_elbow_moves_the_arm` (draw_frame with `elbow_r=(6,0)` differs from `Pose()` near the elbow and keeps the hand pixel), `test_a_bent_limb_stays_in_the_cell` (hand `(0,-40)`, elbow `(10,-10)`: no pixel outside the cell), `test_key_poses_take_elbows_knees_and_sway` (parse_pose accepts them).
- [ ] Step 2: run, see them fail.
- [ ] Step 3: implement; straight limbs return the exact old computations (`capsule(root,end)`, `_lerp`).
- [ ] Step 4: `pytest tests/test_spritegen.py -q` → all pass, **including `test_generated_sheets_are_up_to_date`** (no sheet changed).
- [ ] Step 5: commit `feat: limbs that bend at the elbow and the knee, for real poses`.

### Task 2: Poses in look files and sheets

**Files:** Modify `tools/spritegen/look.py` (`Look.poses`, `parse_poses`), `tools/spritegen/sheet.py` (anims `pose_<id>`, `[poses.<id>]` lines), `jojo_arena/engine/sprites.py` (`PoseInfo`, `SheetSprites.poses`). Tests: `tests/test_spritegen.py`, `tests/test_sprites.py`.

**Interfaces — Produces:**
- `@dataclass(frozen=True) class PoseInfo: id: str; label: str; label_en: str; source: str; stand: bool; stand_offset: tuple[float, float]` in `jojo_arena/engine/sprites.py`.
- `SpriteSet.poses: dict[str, PoseInfo]` (ordered as in the look; `{}` for placeholders and sheets without poses).
- Look TOML: `[poses.<id>]` keys `label`, `label_en`, `source`, `stand` (bool, default false), `stand_offset` ([x, y], default [-14, -8]), `fps` (default 4), `loop` (default true), views as `[[poses.<id>.down]]`… — the same key-pose machinery as `[anims]`. A Stand's look may give poses with frames only.

- [ ] Step 1: tests — a look with two poses builds anims `pose_a`, `pose_b` and the sheet TOML holds `[poses.a]` with label/label_en/source/stand/stand_offset; SheetSprites reads them back in order; a pose without `label`/`source` in a fighter look is refused (Stand looks: frames only, allowed); an unknown pose key is refused.
- [ ] Step 2: fail. Step 3: implement. Step 4: tests pass, sheets still up to date. Step 5: commit `feat: poses in look files, written into the sheets with their source`.
